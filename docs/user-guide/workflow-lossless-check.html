Lossless Check (spectral analysis)

The Lossless Check tab scans a folder of audio files and uses spectral analysis (FFT) to detect whether lossless files (FLAC, WAV, AIFF) are actually re-encoded from lossy sources such as MP3. Files with a sharp high-frequency cutoff are flagged as likely transcodes, with an estimated source bitrate. You can save reports for later reference when sourcing better-quality replacements.

Why this matters. A FLAC file is only truly lossless if the original source was lossless. When someone converts an MP3 to FLAC, the file is larger but the audio quality is unchanged — the high frequencies lost during MP3 encoding cannot be recovered. This tool helps you identify those files so you can replace them with genuine lossless copies.

How spectral analysis works

Lossy codecs like MP3 apply a low-pass filter that removes frequencies above a threshold determined by the bitrate. A 128 kbps MP3 typically cuts off around 16 kHz, while a 320 kbps MP3 cuts at roughly 20.5 kHz. When that MP3 is re-encoded to FLAC, the cutoff remains — there is a sharp drop in spectral energy where the original encoder stopped.

DJ MetaManager decodes a 30-second segment from the middle of each track, computes the frequency spectrum using a Fast Fourier Transform (FFT), and looks for that characteristic energy drop in the 14–21 kHz range. If a steep cutoff is found, the file is flagged as a likely transcode and the estimated source bitrate is reported.

Step 1 — Select a folder

Enter a folder path or click Choose folder… to open the folder navigator. Optionally tick Include subfolders to scan recursively. Click Scan folder to list all supported audio files (FLAC, WAV, AIFF, MP3, M4A, OGG).

The scan reports how many files were found. All formats are listed, though the analysis is most meaningful for lossless containers (FLAC, WAV, AIFF) — MP3 and M4A files will always show a frequency cutoff since they are already lossy.

Step 2 — Analyse

Click Analyze all to process each file sequentially. A progress bar shows the current file and overall completion. Results appear in the table as each file finishes:

Column Meaning
Filename The audio file name.
Format File extension badge (FLAC, WAV, AIFF, MP3, etc.).
Sample Rate The file's sample rate (e.g. 44.1 kHz, 48 kHz).
Duration Track length.
Verdict Lossless — no cutoff detected, appears genuinely lossless.
Transcode — sharp frequency cutoff found, likely re-encoded from a lossy source.
Inconclusive — analysis could not determine with confidence (e.g. very short file, low sample rate).
Est. Source For transcodes: estimated MP3 bitrate of the original source (e.g. “~192 kbps MP3”).
Cutoff The detected frequency cutoff in kHz (e.g. 18.5 kHz).
Confidence How confident the detection is: High, Medium, or Low.

Filter buttons

After analysis, use the filter buttons above the table to show All, Transcodes only, Lossless only, or Other (inconclusive/error). The summary line shows counts for each category.

Saved reports

After a complete analysis, click Save report to store the results on the server. Saved reports appear in the Saved Reports card at the top of the page, showing the folder name, date, file count, and verdict breakdown.

Click Load on any saved report to view its results again. Use the × button to delete a report you no longer need.

Reports are useful for tracking which folders you have already checked and for planning which tracks to source in better quality. Each report stores the full analysis results including filenames, verdicts, and bitrate estimates.

Storage. Reports are saved as JSON files in lossless_reports/ (under ~/Library/Application Support/DJ MetaManager/ for the packaged app, or next to app.py in development). They survive app rebuilds.

Bitrate estimation reference

The estimated source bitrate is based on the detected frequency cutoff:

Cutoff frequency Estimated source
≤ 16.5 kHz~128 kbps MP3
16.5 – 17.5 kHz~160 kbps MP3
17.5 – 19.0 kHz~192 kbps MP3
19.0 – 19.8 kHz~256 kbps MP3
19.8 – 20.8 kHz~320 kbps MP3
> 20.8 kHzLossless (no cutoff)

These thresholds are approximate. Different MP3 encoders (LAME, Fraunhofer, etc.) may use slightly different cutoff frequencies at the same bitrate. The confidence level reflects how sharp and clear the cutoff is.

Tips

  • Focus on FLAC/WAV/AIFF files. Analysing MP3 or M4A files will always show a cutoff — that is expected since they are already lossy. The tool is most useful for checking lossless containers.
  • Save reports before sourcing replacements. Use the transcode filter to see only the files that need replacing, then save the report. When you find better copies, re-scan the folder and compare.
  • Low sample rate files. Files with sample rates below 32 kHz (e.g. old 22 kHz recordings) have a Nyquist frequency below the typical MP3 cutoff range, so the analysis may be inconclusive.

Requirements

Lossless Check requires numpy (listed in requirements.txt) and ffmpeg/ffprobe (same as Extract and Normalise). No additional setup is needed.
