Capture Playlist

The Capture Playlist tab automates recording individual tracks from an Apple Music playlist as separate, lossless 24-bit FLAC files. DJ MetaManager controls Music playback, records each track one at a time through a virtual audio device, verifies the output, and applies metadata from the playlist — producing Rekordbox-ready files without manual intervention.

How it works

  1. Select a playlist from your Music library.
  2. DJ MetaManager snapshots the playlist order and metadata.
  3. For each track: the recorder is armed, Music plays the track once, audio is captured as FLAC, and the file is verified and tagged.
  4. Completed files appear in your output folder, ready for Rekordbox import.

The recorder is always confirmed active before Music starts playing, with a short pre-roll and post-roll to ensure no audio is clipped.

Audio routing

Capture records through OBS Studio, which listens to a BlackHole virtual audio device. Because BlackHole operates at the macOS HAL (Hardware Abstraction Layer) level, it receives audio after DRM decryption — so it works with Apple Music streaming content where other capture APIs (ScreenCaptureKit, Core Audio Process Taps) deliver silence. OBS manages the audio device clock internally, which produces reliable recordings without the sample-rate glitches, speed changes, or crackle that direct FFmpeg capture is prone to.

DJ MetaManager drives OBS remotely over the OBS WebSocket API: for each track it tells OBS to start recording, plays the track once in Music, then tells OBS to stop — producing one MKV per track with a 24-bit lossless audio track. DJ MetaManager then converts each MKV to 24-bit FLAC, verifies it, and applies metadata and artwork from the playlist.

No SoundSource / SoundPipe required. Earlier versions routed Music through Rogue Amoeba’s SoundSource (a paid app) into BlackHole for direct FFmpeg capture. That path has been retired in favour of OBS, which is free, open source, and far more robust. You no longer need SoundSource or SoundPipe.

Required software

  • BlackHole — free virtual audio device for macOS (the 16-channel version, BlackHole 16ch, is recommended).
  • OBS Studio — free, open-source recorder. Includes the obs-websocket server used to control it.

macOS audio setup

  1. In System Settings → Sound, set the system output to BlackHole 16ch so Music plays into the virtual device.
  2. Open Audio MIDI Setup, select BlackHole 16ch, and set its sample rate to 44.1 kHz with output volume at full. Match this rate in OBS (below).
  3. Set the Apple Music app volume to around 90% — a small amount of headroom below 100% avoids inter-sample clipping. Leave EQ off.

Because Music plays into BlackHole (not your speakers), you won’t hear the tracks during capture. If you want to monitor, create a Multi-Output Device in Audio MIDI Setup that includes both BlackHole 16ch and your headphones/speakers, and use that as the system output.

OBS setup

  1. In OBS, add an Audio Input Capture source and point it at BlackHole 16ch. Name it something recognisable, e.g. “DJ Audio”.
  2. In the Audio Mixer (or Advanced Audio Properties), keep only the channels carrying the Music signal and mute the rest so system sounds and notifications aren’t captured. In a typical BlackHole 16ch setup this means muting channels 1/2 (system) and leaving 3/4 at 0 dB — play a track and watch the meters to confirm which pair carries the signal.
  3. Under Settings → Output → Recording, set Recording Format to MKV (Matroska) and the Audio Encoder to a lossless 24-bit codec (FLAC or ALAC). Set the audio sample rate under Settings → Audio to 44.1 kHz to match BlackHole.
  4. Enable the WebSocket server under Tools → WebSocket Server Settings: tick Enable WebSocket server, note the Port (default 4455), and set a password (use Show Connect Info to view it).

Connect DJ MetaManager to OBS

Enter the OBS WebSocket details in config.json under capture.obs (or the Settings panel):

"capture": {
  "backend": "obs",
  "obs": { "host": "127.0.0.1", "port": 4455, "password": "your-obs-password" }
}

OBS may regenerate the WebSocket password when the server is toggled off and on. If preflight reports an authentication error, re-copy the password from Show Connect Info.

Audio routing chain

Apple Music → System output: BlackHole 16ch (44.1 kHz)
    → OBS “DJ Audio” audio input capture (BlackHole 16ch)
        → Audio Mixer: mute system channels (1/2), keep Music channels (3/4)
        → OBS records MKV with 24-bit lossless audio
    → DJ MetaManager (OBS WebSocket) — start/stop per track
        → FFmpeg converts MKV → 24-bit FLAC

With this setup, only the Music channels reach the recording. Other apps (browsers, system notifications) land on the muted channels and are never captured.

Capture workflow

1. Setup

  1. Open the Capture Playlist tab.
  2. Select a playlist from the dropdown (click Refresh if you recently changed playlists in Music).
  3. Review the track preview table — it shows the exact order and metadata that will be used.
  4. Set the output folder (defaults to the value in Settings, e.g. ~/Music/playlist_recordings). Use Choose folder… to browse.

2. Preflight

  1. Click Run preflight to verify Music is accessible, DJ MetaManager can reach OBS over the WebSocket, OBS is not already recording, FFmpeg/FFprobe are available, and disk space is sufficient.
  2. Before starting, play a track in Music and glance at the OBS Audio Mixer to confirm the Music channels show a healthy signal and the muted channels stay silent.

The Test signal button applies only to the legacy direct-BlackHole backend, which measures channel levels through FFmpeg. With the OBS backend you confirm levels in OBS’s own mixer instead.

3. Capture

  1. Click Start capture. DJ MetaManager takes over Music playback.
  2. The running view shows the current track, progress bar, completed/failed/pending counts, and estimated time remaining.
  3. Each track is: armed → pre-roll → played once → post-roll → stopped → verified → tagged → completed.
  4. You can navigate away from the tab without stopping the capture. Return to see current progress reconstructed from server state.

4. Controls during capture

  • Pause after track — finishes the current track, then pauses. Resume later.
  • Stop after track — finishes the current track, then stops the session.
  • Emergency stop — stops Music and the recorder immediately. The current track is marked interrupted and can be retried.

5. Review

After completion (or pause/stop), the review card shows a summary of completed, failed, and skipped tracks. Failed tracks can be retried or skipped. Use New capture to start a fresh session.

Output

Completed files are placed in the output folder as Artist - Title.flac. Each file is:

  • 24-bit FLAC at the capture device’s sample rate (44.1 kHz with the setup above), converted from the OBS MKV
  • Verified by FFprobe (codec, channels, sample rate, bit depth)
  • Tagged with title, artist, album, year, genre, and track number — plus artwork — from the playlist snapshot
  • No normalisation, gain, or EQ applied — use the Normalise tab afterwards if needed
“Resampled” vs “Transcode” in Lossless Check. Apple Music lossless tracks are often hi-res (48/96 kHz). When captured through a 44.1 kHz device, macOS sample-rate-converts them, leaving a gentle high-frequency rolloff. The Lossless Check tool recognises this and reports such files as Resampled (a lossless source that was sample-rate-converted) rather than a lossy Transcode. To keep the full bandwidth, set BlackHole and OBS to a higher rate (e.g. 96 kHz) so no downsampling occurs.

Settings

Capture settings are configured under Settings → Capture — output folder and in the capture section of config.json:

  • backend — recording backend, obs (default, recommended) or blackhole (legacy direct-FFmpeg capture)
  • obs.host / obs.port / obs.password — OBS WebSocket connection (default host 127.0.0.1, port 4455)
  • output_dir — where completed FLAC files are placed (falls back to the destination folder if empty)
  • blackhole_device_name / blackhole_channels — only used by the legacy blackhole backend (defaults: BlackHole 16ch, channels [1, 2])
  • pre_roll_ms / post_roll_ms — silence buffer before/after playback (default: 750ms each)
  • play_start_timeout_s — how long to wait for Music to start playing (default: 15s)
  • playback_stall_timeout_s — stop if playback stalls for this long (default: 12s)
  • duration_grace_s — allowed overrun past planned duration (default: 15s)
  • disk_reserve_gb — minimum free disk space to maintain (default: 5 GB)

Troubleshooting

Cannot connect to OBS

  • Make sure OBS is running before you run preflight or start a capture.
  • Confirm the WebSocket server is enabled under Tools → WebSocket Server Settings and the port matches capture.obs.port (default 4455).
  • If preflight reports an authentication error, re-copy the password from Show Connect Info into capture.obs.password — OBS can regenerate it when the server is toggled.
  • Preflight also fails if OBS is already recording; stop the existing recording first.

Silent capture (no audio in the FLAC file)

  • Confirm the system output is set to BlackHole 16ch (not your speakers) so Music actually plays into the virtual device.
  • In the OBS Audio Mixer, verify the Music channels are unmuted and show a signal while a track plays — and that you didn’t mute the wrong pair.
  • Check that OBS’s Audio Input Capture source is pointed at BlackHole 16ch.

Wrong speed, crackle, or sample-rate glitches

  • Ensure the sample rate matches across the chain: Audio MIDI Setup (BlackHole 16ch), OBS → Settings → Audio, and Music playback should all be 44.1 kHz.
  • A mismatch between the device rate and the OBS audio rate is the usual cause of speed changes or clicks.

Music permission denied

If DJ MetaManager cannot control Music, go to System Settings → Privacy & Security → Automation and enable the Music checkbox for Terminal (or the DJ MetaManager app if using the packaged build).

BlackHole device not found

Install BlackHole (the 16-channel version). After installation, restart macOS audio (or log out and back in), set it as the system output, and it will appear as a device in OBS.

DRM note. This feature records normal system audio playback through a virtual audio device. It does not decrypt, bypass, or circumvent any DRM. Users are responsible for complying with applicable laws, licences, and service terms.
